# MSPM0 代码生成

代码生成器的 `libxr mspm0 setup` 命令把 TI SysConfig 工程接入 LibXR：解析工程根目录的 `.syscfg` 文件，生成 C++ 初始化代码。SysConfig 负责时钟、引脚、DMA 通道和外设的配置（`main.c` 中的 `SYSCFG_DL_init()`），生成的代码声明 LibXR 对象并把对象注册到 XRobot，构造参数全部使用 SysConfig 生成的宏。

---

## 快速使用

在 SysConfig 工程根目录下执行：

```bash
libxr mspm0 setup -d .
```

工程根目录放置一个 `.syscfg` 文件。该命令依次完成以下步骤：

1. 工程目录还没有 `.gitignore` 时创建一个，忽略 `build`、`.history`、`.cache`、`CMakeFiles` 和 `.config.yaml`；已有的 `.gitignore` 保持不变；
2. 解析 `.syscfg`，写出 `.config.yaml`；
3. 在 `User/` 下生成 `app_main.cpp`、`app_main.h` 和 `libxr_config.yaml`。

`--xrobot` 和 `--no-xrobot` 都不写时，沿用输出文件现在的选择，新文件不使用 XRobot；使用 XRobot 时生成 `XR_REGISTER` 注册和 `XROBOT_MAIN();`，命令结束前提示运行 `xrobot gen` 更新 `User/xrobot_main.hpp`。已有的 `app_main.cpp` 不是 `libxr gen` 生成时，setup 给出警告并列出将被替换的行，User Code 区域之外的内容全部重新生成。

---

## SysConfig 输出的来源

解析读取两个来源：`.syscfg` 本身（外设实例、参数和引脚分配），以及 SysConfig 生成的 `ti_msp_dl_config.h/.c`（实际写出的宏名、`CPUCLK_FREQ`、ULPCLK 分频和各实例的时钟配置）。

设置了环境变量 `SYSCONFIG_TOOL` 和 `MSPM0_SDK_INSTALL_DIR` 时，解析对 `.syscfg` 运行一次 SysConfig，输出写入临时目录；这两个变量与 BSP 的 `cmake/MSPM0SysConfig.cmake` 使用的是同一组。没有设置这两个变量时，解析复用工程 `build*`、`cmake-build*` 或 `out` 目录下比 `.syscfg` 新的生成输出。复用只比较修改时间：`.syscfg` 被替换为修改时间更旧的文件时仍会复用旧输出，此时重新构建一次，或设置这两个变量后再运行。

BSP 的 CMake 在 configure 阶段对 `.syscfg` 运行 SysConfig，输出在构建目录的 `syscfg/` 下，`.syscfg` 改动后自动重新生成，见 [MSPM0 环境配置](../../env_setup/mspm0.md)。

## app_main.cpp

`app_main.cpp` 包含 LibXR 初始化函数 `app_main()`。`/* User Code Begin N */` 与 `/* User Code End N */` 之间的代码在重新生成时保留，其余部分每次重新生成。生成的外设对象都是 `static` 对象，`app_main()` 返回后仍然有效；长期使用的局部对象声明为 `static`。外设对象可以以基类指针传给线程或模块使用，做法见[与XRobot集成](../xrobot_inter.md)。

下面是 bsp-mspm0g3507-mini 生成的 `app_main.cpp` 节选，省略处写作 `// ...`：

```cpp
// Generated by `libxr gen`; do not edit by hand.
// Generated from mspm0g3507_minidb48.syscfg (MSPM0G3507); SysConfig configures the
// clocks, pins, DMA channels and peripherals (SYSCFG_DL_init() in main.c). Put
// application code between the "User Code Begin" and "User Code End" markers.
#include "app_main.h"

#include "libxr.hpp"
#include "mspm0_gpio.hpp"
// ...

using namespace LibXR;

/* User Code Begin 1 */
// KEY interrupt counters, incremented in the GPIO interrupt callbacks.
static std::atomic<uint32_t> key1_irq_count{0};
/* User Code End 1 */

// Input clocks: the BUSCLK of the power domain. PD0 from ULPCLK = CPUCLK_FREQ / 2
// (DL_SYSCTL_setULPCLKDivider) and PD1 from MCLK (CPUCLK_FREQ). The I2C driver resets
// the clock configuration of its peripherals, so the BUSCLK of the domain is the right
// argument.
static constexpr uint32_t PD0_BUSCLK_FREQ = (CPUCLK_FREQ / 2);
static constexpr uint32_t PD1_BUSCLK_FREQ = CPUCLK_FREQ;

// Ownership of the DMA channels that serve a UART transmitter;
// MSPM0_UART_MAIN_INIT checks these names against the ones SysConfig generated.
#define DMA_CH_UART0_TX_LIBXR_UART_IRQN UART_0_INST_INT_IRQN
#define DMA_CH_UART0_TX_LIBXR_UART_TX 1

// DMA buffers. A UART gets 2 x N bytes for its two transmit halves; the receive side
// runs on byte interrupts. The SPI DMA buffers are split in two halves as well; the
// I2C driver uses polling, its buffer is the staging area for DMA transfers.
alignas(size_t) static uint8_t uart0_tx_buf[2 * 128];
// ...
alignas(4) static uint8_t i2c0_buf[32];

extern "C" void app_main(void)
{
  /* User Code Begin 2 */
  /* User Code End 2 */

  // Timebase and platform
  static MSPM0Timebase timebase;
  PlatformInit();

  // GPIO: SysConfig configured LED1 (PB8), LED2 (PA16) as output pins and KEY1 (PB24),
  // KEY2 (PB20) as input pins. The interrupt edge comes from SysConfig; RegisterCallback
  // and EnableInterrupt belong to the consumer (a Module or the User Code).
  static MSPM0GPIO LED1(GPIO_LEDS_PIN_LED1_PORT, GPIO_LEDS_PIN_LED1_PIN,
                        GPIO_LEDS_PIN_LED1_IOMUX);
  // ...

  // UART: TX with DMA; the receive side runs on byte interrupts.
  static MSPM0UART uart0(MSPM0_UART_MAIN_INIT(UART_0, DMA_CH_UART0_TX, uart0_tx_buf,
                         sizeof(uart0_tx_buf), 5, 128));
  // ...

  // I2C: polling; the buffer stages DMA transfers.
  static MSPM0I2C i2c0(MSPM0_I2C_INIT(I2C_0, PD0_BUSCLK_FREQ, i2c0_buf, sizeof(i2c0_buf),
                       8), {I2C_0_BUS_SPEED_HZ});

  // SPI: DMA for transfers longer than the threshold.
  static MSPM0SPI spi1(MSPM0_SPI_INIT(SPI_1, PD1_BUSCLK_FREQ, DMA_CH_SPI1_RX,
                       DMA_CH_SPI1_TX, spi1_rx_buf, sizeof(spi1_rx_buf), spi1_tx_buf,
                       sizeof(spi1_tx_buf), 3));

  // PWM: the channels of one timer share one period, which SysConfig configures.
  static MSPM0PWM pwm_tima1_c0(MSPM0_PWM_CH(PWM_TIMA1, 0));
  static MSPM0PWM pwm_tima1_c1(MSPM0_PWM_CH(PWM_TIMA1, 1));

  // Terminal on uart0
  STDIO::read_ = uart0.read_port_;
  STDIO::write_ = uart0.write_port_;
  static RamFS ramfs("XRobot");
  static Terminal<32, 32, 5, 5> terminal(ramfs);
  /* User Code Begin 3 */
  KEY1.SetConfig({GPIO::Direction::FALL_INTERRUPT, GPIO::Pull::NONE});
  KEY1.RegisterCallback(GPIO::Callback::Create(OnKeyInterrupt, &key1_irq_count));
  KEY1.EnableInterrupt();
  /* User Code End 3 */
  XROBOT_MAIN();
}
```

每个外设对象以 SysConfig 生成的宏构造，例如 GPIO 的 `GPIO_LEDS_PIN_LED1_PORT`、UART 的 `UART_0`。各对象的中断由 LibXR 驱动在构造时开启并设置优先级，SysConfig 中对同一中断的设置被驱动覆盖；引脚中断的边沿来自 SysConfig，回调的登记（`RegisterCallback` 和 `EnableInterrupt`）由使用方完成，模块或 User Code 中的做法见上例的 User Code 区域。

## 生成的对象与命名

生成的对象来自 LibXR 有驱动的配置：UART、控制器模式的 I2C 和 SPI、PWM；GPIO 引脚各生成一个对象。其余配置（ADC12、DAC12、MCAN、QEI、目标模式的 I2C、外设模式的 SPI 等）列入配置摘要的 Other，只作展示。

对象的命名：

| 配置 | 对象名 | 例子 |
| --- | --- | --- |
| GPIO | SysConfig 中引脚的标签（`$name` 去掉 `PIN_` 前缀） | `LED1`、`KEY1` |
| UART、I2C、SPI | 外设实例名的小写 | `uart0`、`i2c1`、`spi1` |
| PWM | `pwm_<定时器>_c<通道号>` | `pwm_tima1_c0` |

定时器的每个 CCP 通道生成一个 PWM 对象，同一 TIMER 的通道共用一个周期，周期由 SysConfig 配置。`libxr_config.yaml` 给同一定时器的通道设置了不同的频率时，生成器给出警告，以最后一次 `SetConfig` 为准。

各配置的生成要求：

- UART 需要发送 DMA 通道，接收默认按字节中断（`MSPM0_UART_MAIN_INIT`）。UART Extend 实例配置了接收 DMA 时按循环 DMA 接收（`MSPM0_UART_EXTEND_INIT`，接收环的字节数见 `rx_dma_buffer_size`），接收通道须为 FULL-DMA 通道；UART Main 实例的接收 DMA 通道用不上，生成器给出警告。缺少发送 DMA 的 UART 使生成报错。
- SPI 需要一对 DMA 通道，否则生成报错。
- I2C 以轮询工作，缓冲区是 DMA 传输的中转。

## 时钟

生成的代码为用到的电源域定义 BUSCLK 常量：PD1 的 BUSCLK 是 `CPUCLK_FREQ`，PD0 的是 `CPUCLK_FREQ` 除以 ULPCLK 分频（生成代码里的 `DL_SYSCTL_setULPCLKDivider`，默认 1）。I2C 驱动自行重设所辖外设的时钟配置（BUSCLK、分频 1），构造实参取所在电源域的 BUSCLK；SPI 驱动沿用 SysConfig 写下的时钟配置，构造实参取 SysConfig 选择的时钟源（BUSCLK、MFCLK 的 4 MHz 或 LFCLK 的 32.768 kHz）除以分频，其他时钟源使生成报错。SysConfig 为 I2C 和 SPI 输出的宏不含时钟频率，工程缺少电源域或 `CPUCLK_FREQ` 时生成报错。UART 直接引用 SysConfig 的 `INST_FREQUENCY` 宏，PWM 的源时钟由驱动按 `INST_CLK_FREQ` 反推。

## libxr_config.yaml

`User/libxr_config.yaml` 保存代码生成的设置。文件不存在时按默认值新建；之后每次生成补上缺少的设置，已有的值保持不变。外设的设置段只在工程有对应外设时写入，段中每个实例一项，键为小写的实例名，PWM 的键为对象名。值为 null（YAML 中只写了键）时取默认值；缓冲区和队列必须是正整数。

下表列出各设置段，默认值与 STM32 不同的单独说明：

| 段 | 键与默认值 | 说明 |
| --- | --- | --- |
| `UART` | `tx_buffer_size: 128`、`rx_buffer_size: 128`、`tx_queue_size: 5` | UART Extend 实例另有 `rx_dma_buffer_size: 128`（偶数） |
| `I2C` | `buffer_size: 32`、`dma_enable_min_size: 8` | |
| `SPI` | `tx_buffer_size: 32`、`rx_buffer_size: 32`、`dma_enable_min_size: 3` | |
| `PWM` | `frequency`（默认 null） | null 时不调用 `SetConfig`，见[生成的对象与命名](#生成的对象与命名) |
| `Terminal` | `read_buff_size: 32`、`max_line_size: 32`、`max_arg_number: 5`、`max_history_number: 5` | 终端的模板参数，见[串口与终端](../stm32/uart.md) |

`terminal_source` 遵循 STM32 的约定：空值或 `none` 不生成终端；文件里还没有这个键时（第一次生成）选第一个 UART。`tx_buffer_size` 的取值还须满足驱动的断言：发送缓冲为 2 × N 字节，2 × N 是 `2 * alignof(size_t)` 的倍数（Cortex-M0+ 上即 N 为 4 的倍数），且 N 不超过单次 DMA 传输的 0xFFFF 字节。设置键不区分大小写，文件中已有的写法保持不变。

以下是 bsp-mspm0g3507-mini 首次生成的 `User/libxr_config.yaml`：

```yaml
generator: 6.0.0
terminal_source: uart0
SPI:
  spi1:
    tx_buffer_size: 32
    rx_buffer_size: 32
    dma_enable_min_size: 3
I2C:
  i2c0:
    buffer_size: 32
    dma_enable_min_size: 8
  i2c1:
    buffer_size: 32
    dma_enable_min_size: 8
Terminal:
  read_buff_size: 32
  max_line_size: 32
  max_arg_number: 5
  max_history_number: 5
UART:
  uart0:
    tx_buffer_size: 128
    rx_buffer_size: 128
    tx_queue_size: 5
  uart1:
    tx_buffer_size: 128
    rx_buffer_size: 128
    tx_queue_size: 5
PWM:
  pwm_tima1_c0:
    frequency:
  pwm_tima1_c1:
    frequency:
```

I2C 的总线速率和 UART 的波特率来自 SysConfig 工程（如 `I2C_0_BUS_SPEED_HZ`），`libxr_config.yaml` 中没有对应的设置。

## 重新生成代码

修改 `.syscfg` 或 `User/libxr_config.yaml` 后，在工程根目录重新运行 `libxr mspm0 setup -d .`，或只重新生成 `User/` 下的文件：

```bash
libxr parse -d .
libxr gen -i .config.yaml -o User/app_main.cpp
```

`.config.yaml` 由 `libxr parse` 写出，新克隆的工程里没有这个文件，先运行 `libxr parse`。VS Code 扩展的 Generate LibXR Code 动作依次运行这两条命令，见 [VS Code 扩展](../../env_setup/README.md#vs-code-扩展)。

## 可选参数

`libxr mspm0 setup` 的参数如下，`libxr mspm0 setup --help` 同样列出这些参数。

| 参数       | 说明                        |
| ---------- | --------------------------- |
| `-d`, `--directory` | 工程目录：根目录下有一个 `.syscfg` 文件（默认：当前目录） |
| `-o`, `--output` | 输出的 C++ 文件（默认：DIRECTORY 下的 `User/app_main.cpp`） |
| `--xrobot` / `--no-xrobot` | 生成或不生成 `XR_REGISTER` 注册与 `XROBOT_MAIN();`，见 [与XRobot集成](../xrobot_inter.md)；都不写时沿用输出文件现在的选择，新文件不使用 XRobot |
| `--libxr-config` | libxr_config.yaml 的路径或 URL（默认：输出文件旁边的 `libxr_config.yaml`） |
| `--verbose` | 输出调试日志 |
