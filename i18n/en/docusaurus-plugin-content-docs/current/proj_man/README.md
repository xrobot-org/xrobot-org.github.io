# Project Management (XRobot)

XRobot (the `xrobot` command) resolves reusable C++ Modules to exact commits and generates a static C++ application entry for LibXR BSPs. It is not a build system: after `xrobot setup`, build with the BSP's own CMake, presets, Docker or vendor commands. LibXR is usable without XRobot.

---

## Installation

```bash
pip install xrobot==1.0.0
```

A BSP pins the tool version in `Modules/modules.yaml` (`xrobot: 1.0.0`); install that version. When the installed version differs from the pin, `xrobot setup` and `xrobot gen` warn and `xrobot setup --frozen` fails. STM32 BSPs also use the code generator `libxr` (`pip install libxr==6.0.0`), pinned by `generator:` in `User/libxr_config.yaml`.

`pipx install xrobot==1.0.0` installs into an isolated environment. Do not install the same package with both pip and pipx.

In `VS Code`, the extension [`XRobot.xrobot`](https://marketplace.visualstudio.com/items?itemName=XRobot.xrobot) (2.0.0 and later for XRobot 1.0) shows what `xrobot describe` reports and makes every change through an `xrobot` command.

---

## BSP Layout

The BSP root is the nearest directory containing `Modules/modules.yaml`. Every command works from any subdirectory of the BSP, or with `-C DIR`.

| File | Committed | Meaning |
| --- | --- | --- |
| `Modules/modules.yaml` | yes | Requested Modules (`owner/Repo@ref`) and the `xrobot:` tool pin |
| `Modules/sources.yaml` | yes | Module catalogs (`index.yaml`) and their priorities |
| `xrobot.lock` | yes | Exact commit of every Module in the dependency closure |
| `User/*.yaml` | yes | Application configurations (products); `User/libxr_config.yaml` is not one |
| Entry source under `User/` | yes | Registers BSP objects with `XR_REGISTER` and calls `XROBOT_MAIN()` |
| `Modules/<owner>/<Repo>/` | no | Module checkouts at the locked commits |
| `Modules/CMakeLists.txt` | no | Generated by `xrobot setup` |
| `User/xrobot_main.hpp` | no | Generated entry for the selected product |

`xrobot init` creates `Modules/modules.yaml`, `Modules/sources.yaml` and `User/xrobot.yaml` in the current directory and adds the generated files to `.gitignore`.

## Quick Start

```bash
xrobot init
xrobot module add xrobot-org/BlinkLED@dev
xrobot setup                              # fetch, lock, check configs, generate the entry
xrobot instance add xrobot-org/BlinkLED   # adds instance blinkled_0
```

`instance add` writes every constructor parameter with its source default; a dependency without a default is left empty (`null`, "not filled in"). Fill it with the name of a registered BSP object:

```yaml
modules:
  - module: xrobot-org/BlinkLED
    id: blinkled_0
    args:
      - led: LED_R
      - blink_cycle: 250
settings:
  monitor_sleep_ms: 1000
```

The entry source registers the objects that configurations may use and enters the application:

```cpp
#include "xrobot_main.hpp"

// ... construct LED_R and the other BSP objects ...
XR_REGISTER(LED_R, LibXR::GPIO);
XROBOT_MAIN();
```

Generate and build with the native tools:

```bash
xrobot gen
cmake -S . -B build
cmake --build build
```

In STM32 BSPs the entry `User/app_main.cpp` is written by the code generator; see [Integrate with XRobot](../code_gen/xrobot_inter.md).

## Commands

| Command | Purpose |
| --- | --- |
| `xrobot init` | Create the BSP files in the current directory |
| `xrobot setup` | Resolve and lock Modules, check every config, regenerate the entry |
| `xrobot gen [-c CONFIG]` | Generate `User/xrobot_main.hpp` (select a product) |
| `xrobot describe [-c CONFIG]` | Print the BSP state as JSON for editors |
| `xrobot sync [-c CONFIG]...` | Add new fields/parameters with defaults, drop removed ones |
| `xrobot format [--check] [-c CONFIG]...` | Rewrite configs in the canonical layout |
| `xrobot instance [-c CONFIG] add\|set\|remove\|rename` | Edit one instance |
| `xrobot module add\|remove owner/Repo[@ref]` | Edit `Modules/modules.yaml` |
| `xrobot module show MODULE` | Print a Module's manifest and constructors (folder, header or Module id) |
| `xrobot new-module NAME` | Create a Module skeleton (header, CMake, README, CI) |
| `xrobot check-module MODULE` | Write the constructor call used by Module CI (compiled, never executed) |
| `xrobot source ...` | Query or edit catalogs |

`xrobot <command> --help` lists each command's options.
